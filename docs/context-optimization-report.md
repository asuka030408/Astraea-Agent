# Astraea Agent 上下文管理优化报告

## 1. 改动目标与结论

原有 T1–T5 策略只在用户提交新消息前检查一次。Agent 在同一轮中连续调用工具时，后续模型调用仍可能反复携带此前所有工具结果；固定阈值也无法判断哪些结果与当前步骤有关。本次改动把上下文选择移到 **LangChain 每一次模型请求之前**，同时保持完整会话记录和工具执行状态不变。

在构造的 20 组工具结果测试中，下一次请求只发送与问题相关的前 2 组，另 18 组留在外部存储。该场景的模型可见消息从约 **5,291** tokens 降至 **669** tokens（约减少 **87%**，不含固定工具定义开销）。这是特定测试数据的结果，不是通用性能承诺。

## 2. 动态裁剪：每次模型调用重新选择

实现位置：`astraea/context.py` 的 `ContextMiddleware.awrap_model_call` 和 `ContextManager.select`。

1. Agent 图继续持有完整消息列表。中间件通过 `request.override(messages=...)` 只替换**当次模型请求**的消息视图，因此不会改写 LangGraph 状态，也不会把被裁剪内容从会话记录中删除。
2. 一个 AI 工具调用及其所有匹配的工具结果视为不可拆分的组。选择时按当前用户问题和最近的明确模型文字进行本地词项匹配；匹配组优先，不匹配时至少尝试保留最新一组。平行工具调用的结果一起保留，避免孤立的 `ToolMessage`。
3. 单个结果超过分配预算时，模型只看到有界片段和外部记录 ID；完整结果仍可读取。未选中的结果不会以十八条占位消息重新塞进上下文，只会有一条简短的外部存储提示。
4. 普通对话独立选择：优先保留近期或与当前问题相关的用户/助手消息。始终保留本次用户问题。若请求的固定成本已经超过预算，明确报错，不静默丢弃关键内容。

该方法是**词项相关性选择**，不是语义检索或模型判断。语义关联弱、措辞差异大的旧结果可能不会自动入选，但 Agent 可通过外部检索工具找回。

## 3. 压缩策略：按内容类型，而非统一阈值

已移除原先按 30%/60%/75%/90%/95% 逐层执行的 T1–T5 工作流。新策略将工具结果与对话分开处理：

- **工具结果**：完整保存到外部；当次请求按相关性与工具结果预算选取，不再先压缩失败调用、再压缩旧输出。
- **历史对话**：只有超出对话预算时，才调用单独的摘要模型生成任务检查点，保留目标、约束、决策、已完成工作与未解问题。检查点缓存在会话中；没有积累足够新对话时不会在每次模型调用上重复生成。
- **摘要失败**：保留已有检查点、近期消息和外部记录，并记录错误；不把失败的摘要当成已完成状态。

这样，长工具链主要通过动态选择降本，长对话才触发额外的摘要模型调用。摘要不是原文的替代品，完整会话始终保存在 `data/sessions/`。

## 4. 外部存储与按需加载

实现位置：`astraea/context_store.py`、`astraea/tools/context.py`。

每个工具执行完成后，中间件把完整返回内容、调用参数、工具名和状态写到 `data/context/<会话ID>/items/`。原有完整会话也继续保存；这份独立记录便于按 ID 加载和按词检索。文件读取工具返回的内容同样进入外部记录。**注意：** `read_file` 本身仍有 20,000 字符的返回上限，因此外部记录保存的是工具实际返回的内容，不保证是大文件的全部字节。

新增两个按会话绑定的工具：

- `search_context(query)`：从当前会话的历史工具结果中找候选记录，返回 ID、工具和短预览。
- `load_context(context_id)`：按 ID 分段读取某条结果，也可指定 `field="args"` 读取完整调用参数；`task_state` ID 可读取外部任务状态。
- `search_history(query)` 与 `load_history(index)`：从本会话的完整记录中定位并分段读取较早的用户/助手对话，便于摘要遗漏时按需找回原话。

`task_state` 保存最近目标、助手答复与相关文件路径。它是轻量状态线索，会随着已完成回合更新；当前用户消息始终优先于该状态。Web 的“上下文管理”窗口现在展示上一次模型请求视图、本轮最终答复、预算数据以及外部工具记录。旧版 `data/archives/` 继续可读。

这里的外部上下文**属于当前会话**，与跨会话的长期 Memory 分开。`search_memory` 仍负责长期记忆检索。

## 5. Token 预算分配

每次模型调用按实际可用工具计算工具定义成本。系统提示词、工具定义、本次用户消息属于固定成本；长期画像最多使用上下文窗口的 10%，且上限为 2,048 tokens。输出预留 15%（最多 4,096 tokens），另外保留 2% 安全余量。余下的可变输入预算按下表划分：

| 类别 | 可变预算占比 | 用途 |
| --- | ---: | --- |
| 历史对话与检查点 | 46% | 近期对话、相关旧对话和必要时的摘要 |
| 普通工具结果 | 34% | 文件、命令、网页等工具调用和结果 |
| 按需检索结果 | 15% | `search_memory`、`search_context`、`load_context` 的结果 |
| 任务状态与外部提示 | 5% | 外部 `task_state` 和结果已外置的说明 |

空闲预算不会强制填满。最终请求还会进行一次总量检查。`last_budget` 随会话保存，包含各类别实际估算和上限。Token 数由 `cl100k_base` 估算，可能与具体模型提供方的计费计数不同。

## 6. 工具数量准备

原有 6 个内置工具保留；新增 8 个工作区文件工具：`list_files`、`file_info`、`read_file_lines`、`append_file`、`replace_in_file`、`copy_file`、`move_file`、`delete_file`。内置工具现为 **14 个**；加上按会话绑定的 4 个上下文工具，模型至少可见 **18 个自有工具**，另外仍可接入 Fetch、Filesystem、Time 和 Git MCP 工具。本次共新增 12 个工具。

新增文件工具继续限制在配置的工作区内。复制和移动不覆盖已有目标；文本替换要求旧文本恰好出现一次；`delete_file` 把文件移入工作区的 `.astraea-trash`，可恢复。本次只增加工具种类，**没有实现工具选择/路由优化**。

## 7. 验证与当前边界

- `python -m unittest discover -s tests -v`：**32 项通过**。覆盖 20 组工具结果只保留 2 组、会话隔离、外部加载、预算与长期画像上限、检查点复用、平行工具调用配对、真实 LangChain Agent 循环（假模型）、新增文件工具边界，以及原有 Web/Memory/MCP 测试。
- 额外构造场景测量：完整请求 42 条消息、约 5,291 消息 tokens；裁剪后 8 条消息、约 669 消息 tokens，18 组结果外置。
- 未运行真实付费模型的 `tests/live_smoke.py`。它已更新为新策略的可选连续性冒烟测试；真实模型的回答质量仍需人工评估。

当前相关性选择使用本地词项匹配，不具备跨措辞的语义召回或重排。旧对话的摘要可能遗漏细节，因此原文与外部工具结果继续保留并支持按需加载。预算会限制大结果进入模型；如果系统提示词、工具定义和本次问题本身已超出窗口，系统会报错而不是裁剪这些固定部分。
